# Географический индекс зон наблюдения и гипотезы связей документов

Реализованный прототип: Java 17, `OverpassStreets`, `GeoDictionary`, `ProjectLinks`, `Store`, `Geo`.

## 1. Что происходит после рисования полигона

1. Полигон остаётся в GeoJSON (`EPSG:4326`, координаты `[lon,lat]`).
2. Пользователь **явно** нажимает «Улицы». Сервер отправляет один запрос на публичный Overpass (`way["highway"]["name"](south,west,north,east);out body geom;`), получает геометрию OSM ways и проверяет **реальное пересечение линии с полигоном**, а не только попадание конечных точек или bbox. Проверяются и отверстия полигона. В локальной базе остаются `osmId`, `name`, `alt_name` и другие подтверждённые альтернативные наименования; исходные линии можно повторно получить по OSM ID. Результат кэшируется до следующего явного обновления.
3. Кадастровые номера добавляются **отдельно**, импортом GeoJSON `FeatureCollection` (в т.ч. `cad_num`), JSON массива `parcels`, `.txt` или `.csv` со списком номеров. Если импортирована геометрия участка, проверяется геометрическое пересечение с полигоном. Без геометрии это **только ручное отнесение номера к зоне** (`AREA_DECLARED`), не факт пространственного пересечения.
4. По улицам и участкам каждой зоны строится инвертированный индекс Java. Сканирование документов не инициирует загрузку OSM/НСПД: справочник независим от источников публикаций.

**Ограничение:** публичная кадастровая карта на `nspd.gov.ru` предоставляет просмотр общедоступных сведений. Документированный и разрешённый API *массовой* выгрузки всех участков произвольного полигона не подтверждён. Адаптер НСПД специально не реализован как скрейпер закрытых/внутренних адресов. В качестве базового пути принят импорт данных, полученных законно и проверяемо.

OSM публичный Overpass — совместно используемый сервис, поэтому при BBox больше 0,055° по любой оси включается защитный отказ: разбейте полигон на меньшие. Для города целиком используйте региональный OSM-экстракт и локальный индекс, а не десятки тысяч запросов к публичному Overpass.

Источники: https://dev.overpass-api.de/overpass-doc/en/full_data/bbox.html ; https://dev.overpass-api.de/overpass-doc/en/preface/commons.html ; https://osmfoundation.org/wiki/Attribution_Guidelines . Данные OSM лицензируются по ODbL, в приложении сохраняется источник и ссылка на OpenStreetMap.

## 2. Извлечение упоминаний

`GeoDictionary` анализирует `title`, `description`, `evidenceText`, `locationScope`, `workLocation`, `documentText` (длинное поле в JSON ограничено 12 тыс. символов). Не включает `authority`: юридический адрес заказчика не равен адресу работ.

- **CADASTRAL:** только полный кадастровый идентификатор (`16:50:......:...`), ограниченный цифровыми границами; без неполного совпадения префикса. Есть `certainty`: `IMPORTED_GEOMETRY` либо `AREA_DECLARED`.
- **STREET:** последовательность нормализованных слов одного из OSM имён, небольшое склонение прилагательных, подсказка типа объекта (`улица`, `ул.`, `проспект`, `шоссе`...). Частотные однословные имена вроде «Мира» и «Победы» требуют близкого дорожного термина.
- **USER_KEYWORD:** ручные метки остаются слабой подсказкой.

Ответ `/api/events` содержит `geoEvidence` с `areaId`, `kind`, `matchedText`, `object`, `score`, `certainty`, `source`, `explanation`. В интерфейсе это видно в карточке события. **Все текстовые совпадения имеют статус `HINT`, не `MATCH`**, независимо от числа сигналов. `MATCH` сохраняется только для геоточки, вручную/независимо размещённой внутри полигона. В будущем подтверждение линии/контура работ должно стать самостоятельным статусом с источником геометрии.

## 3. Проекты: связи, а не преждевременное объединение

`GET /api/related?eventId={uuid}` возвращает не более 25 кандидатов, связанных с выбранным событием по **полному кадастровому номеру** и/или **названию улицы в той же зоне**. Оценка учитывает независимые признаки и разные стадии (`PREPARATION`, `PROCUREMENT`, `WORKS` и др.).

Статус у всех кандидатов — **`REVIEW`**. Совпадение по одной улице даёт только слабую гипотезу; документы нескольких разных проектов этой улицы автоматически не объединяются. В интерфейсе карточки события отображаются возможные связанные документы. Связи между постановлением, строкой приложения, закупкой, контрактом и геометрией работ нуждаются в следующих опорах: номере самого документа, коде закупки, номере контракта, конкретных границах участка и версии приложения.

## 4. Примеры API

```http
POST /api/areas/{areaId}/streets
Content-Type: application/json

{}
```

Обновляет список улиц из OSM. Это сетевой запрос на несколько секунд; возможно HTTP 429/503. Сбой не заменяет старый список пустым.

```http
POST /api/areas/{areaId}/parcels
Content-Type: application/json

{"source":"Мой экспорт кадастровых объектов", "type":"FeatureCollection", "features":[
  {"type":"Feature","properties":{"cad_num":"16:50:010101:123"},
   "geometry":{"type":"Polygon","coordinates":[[[49.073,55.829],[49.074,55.829],[49.074,55.830],[49.073,55.830],[49.073,55.829]]]}}
]}
```

*Идентификатор и геометрия в примере синтетические.* Для ручного списка без геометрии: `{"parcels":[{"cadastralNumber":"16:50:010101:123"}]}`.

```http
GET /api/areas/{areaId}/dictionary
GET /api/related?eventId={eventId}
GET /api/events
```

`GET /api/areas` отдаёт только количество улиц и участков, а `/api/export` — полные данные. Данные сохранены в `data/activist.json` (не коммитить в GitHub). Предусмотрена миграция старого JSON без полей `streets`/`parcels`.

## 5. Рекомендуемая постоянная схема после MVP

Для нескольких пользователей и документов объёмом гигабайты:

```sql
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
-- Схема иллюстративная, пока не внедрена в Maven MVP.
CREATE TABLE watch_area(id uuid PRIMARY KEY, name text, geom geometry(MultiPolygon,4326));
CREATE TABLE geo_object(id bigint PRIMARY KEY, kind text, canonical_id text,
                        name text, geom geometry(Geometry,4326), source text);
CREATE INDEX geo_object_geom_gix ON geo_object USING GIST (geom);
CREATE INDEX watch_area_geom_gix ON watch_area USING GIST (geom);
CREATE INDEX geo_object_name_trgm ON geo_object USING GIN (name gin_trgm_ops);
-- Для обогащения зон: SELECT o.id FROM geo_object o JOIN watch_area a
--   ON ST_Intersects(o.geom,a.geom) WHERE a.id = :area_id;
```

Дополнительно понадобятся `document`, `document_version`, `extracted_entity`, `document_geo_candidate`, `project`, `project_document_link` и журнал смены статусов. Сырые XML, PDF и GeoJSON сохраняются с SHA-256 и временем скачивания. Полнотекстовый индекс — **Apache Lucene** (либо полнотекстовый поиск PostgreSQL на старте), не отдельный ELK ради нескольких тысяч объектов. Механизм простых кандидатов из MVP заменяется нормальной процедурой human-in-the-loop подтверждения связей.

## 6. Чего пока нет

- Подтверждённой автоматической выдачи кадастровых объектов непосредственно НСПД по произвольному полигону.
- Контуров конкретных дорожных работ из чертежей/PDF и сопоставления километров/пикетажа/номеров домов с OSM-сегментами.
- Нормального морфологического анализа русского и татарского языков; встроенная нормализация эвристическая.
- Версионированного хранилища всех документов и полноценного графа проектов.
- Систематических проверок полноты обновлений OSM, кадастра и ведомственных реестров.

Прототип сохраняет события «без географии» в очереди: отсутствие совпадений **не доказывает**, что событие вне выбранных территорий.
