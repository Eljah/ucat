# Исследование ЕИС и PDF-приложений: реализация и ограничения (20 октября 2026)

## Факты о ЕИС

С 01.01.2025 бывший FTP-сервис машиночитаемых документов заменён сервисами отдачи документов. Для физического лица используется `getDocsIP`, для юридического лица — `getDocsLE`; нужна регистрация получателя в ЕИС через ЕСИА. Регистрация участника торгов — другая задача, не путать с получателем открытых данных.

Подтверждённые публикации:
- Сообщение Казначейства/официального Telegram-канала ЕИС: https://t.me/s/gis_eiszakupki?before=2018
- О порядке регистрации: https://xn--80aahqcqybgko.xn--p1ai/141/96/40178/40245/84822.html
- Личный кабинет: https://zakupki.gov.ru/pmd/auth/welcome (вход через ЕСИА).
- Разбор SOAP-запроса и ответа с примером: https://habr.com/ru/articles/869934/ (материал разработчика, НЕ официальная документация).
- Описание форматов — искать **актуальную версию** «Альбома ТФФ» в разделе «Документы» ЕИС, XSD: https://int44.zakupki.gov.ru/eis-integration/services/getDocsIP?xsd=getDocsIP-ws-api.xsd

В коде `EisSoapClient` реализован GET по `archiveUrl` и SOAP-запрос `getDocsByOrgRegionRequest` (POST XML). Для примера подтверждён тип документа `epNotificationEF2020`, регион регистрации заказчика для Татарстана — 16, подсистема `PRIZ`. Для успешного SOAP-запроса важен порядок XML-тегов `index`, затем `selectionParams`, внутри последнего `orgRegion`, `subsystemType`, `documentType44`, `periodInfo`. Токен передаётся в SOAP-заголовке `individualPerson_token` и при скачивании архива как HTTP-заголовок. Секрет не логируется и не сохраняется в JSON.

Весь механизм **не является открытым неавторизованным REST API**. При несовпадении XSD, ошибках сервиса, истёкшем токене, неполной выдаче или временной недоступности в UI появляется предупреждение. Отсутствие результатов нельзя считать отсутствием закупок.

## Охват и раннее обнаружение

- **Дата**: без ручного режима опрашиваются сегодня и вчера по московскому времени, чтобы меньше пропускать документы, появившиеся с задержкой.
- **Типы**: по умолчанию проверяется один тип `epNotificationEF2020`. Переменная `ACTIVIST_EIS_TYPES` позволяет перечислить другие разрешённые XSD типы, например `epNotificationEZK2020`; перед включением их необходимо проверить по актуальной схеме ЕИС.
- **Закон**: реализованный запрос — по подсистеме `PRIZ` в ЕИС, то есть **пока не полный охват** 223-ФЗ, всех методов закупок, планов-графиков и контрактов. Для них потребуется схема типов сообщений и дополнительная логика.
- **Регион**: `orgRegion=16` — регион **регистрации заказчика**, а не место строительства. Федеральный заказчик, зарегистрированный в Москве, может строить дорогу в Казани: эта выборка его не найдёт. Дублирование этой региональной выгрузки в масштабах России создаст огромный поток; для таких заказчиков нужен второй канал: публикации Минтранса/Росавтодора, поиск по объекту и точечная загрузка известных номеров извещений (метод `getDocsByReestrNumberRequest`), затем расширение по перечню профильных заказчиков.
- **Предмет**: `roadWorks` фильтрует дорожную тематику. На текущем этапе требуется текстовое упоминание Казани в названии объекта или месте выполнения. Если приложение или техническое задание содержит адрес, но XML не содержит, такая закупка всё ещё может быть пропущена. Это отдельная задача извлечения проектной документации ЕИС.
- **Программа финансирования**: не выводится автоматически из заказчика, суммы или названия объекта. При отсутствии явного упоминания остаётся пустой.

## Реестры актов и большой PDF

Есть юридически значимая связка: `Постановление КМ РТ от 22.01.2026 №30` об автомобильных дорогах на 2026–2028 годы и последующее `Постановление КМ РТ от 20.05.2026 №712`, изменяющее программу. Для мониторинга критично сохранять версии/изменения, а не просто наличие первого акта.

Источники:
- Реестр КМ РТ https://pravo.tatarstan.ru/npa_kabmin/post
- Реестр исполнительного комитета Казани https://pravo.tatarstan.ru/kazan/ispolkom
- Минтранс https://mindortrans.tatarstan.ru/programma-dorozhnih-rabot-na-2026-god.htm
- Текущий набор ссылок на официальном портале https://pravo.tatarstan.ru/npa_kabmin/post?limit=50
- Официальный портал Казани (проекты НПА, ранние сигналы): https://ukp.kzn.ru/nayti-dokument/antikorruptsionnaya-ekspertiza/

В `RoadAnnex` реализован экспериментальный разбор **текстового слоя PDF** (PDFBox 3.0.7), поиск фрагментов с казанскими объектами внутри документа, страница, исходный URL, и флаг `requiresReview`. Примеры компоновки — табличные документы: «г. Казань» как заголовок группы, на последующих строках разные улицы. Библиотека НЕ распознаёт чертежи, карты, координаты, геометрию и сканы без текста; при отсутствии текстового слоя указывается потребность в OCR. Отсутствие выделенной строки в документе **не является отрицательным результатом поиска объекта**.

Безопасность: источники PDF ограничены доменами `pravo.tatarstan.ru` и `mindortrans.tatarstan.ru`, HTTPS, не поддерживаются автоматические редиректы, PDF — до 32 МБ, 180 страниц, не более 3 PDF с одной страницы реестра. PDF-индекс читается через существующий HTML-загрузчик, его селекторы могут измениться. В памяти может потребоваться намного больше 32 МБ — PDFBox декодирует изображения/шрифты/страницы.

## Важные следующие шаги после интеграционного теста

1. Приобрести не платный API, а **получить доступ получателя ЕИС через ЕСИА**, проверить токен/схему/типы документов на реальных публикациях и определить квоты сервиса. Передавать секрет только через env/секрет-хранилище.
2. Собрать эталонные PDF и XML с разными типами закупок из 2026 года и проверить полноту по номерам извещений (пропуски, корректность поля места работ, дубли и изменения).
3. Для PDF со сканами запустить локальный OCR и отдельный алгоритм табличного разбора. Не превращать эвристические текстовые упоминания в геоточки.
4. Отделить `акт → приложение → конкретный объект → закупка → контракт`, связывая идентификаторы и версии. Одна публикация может содержать много дорог.
5. Добавить графическое извлечение осей/полигонов с геопривязкой по подложке и ручную проверку контуров. Только после этого устанавливать пересечение с полигоном пользователя.
6. Рассматривать проекты, разработанные по линии Росавтодора и федеральных учреждений за пределами региона заказчика 16.

`EisAndAnnexTest` проверяет детерминированные XML-запросы и ответы, неверные archiveUrl, ZIP с повторяющимися объявлениями, защиту от XXE и выделение городских строк из синтетического текста приложения. **Он не доказывает работоспособность ЕИС, полноту PDF-парсинга или возможность скачивания с сайта Минтранса на реальном сервере.**
