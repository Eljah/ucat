# Пилот: линейные участки дорог и история проекта (21 октября 2026)

## Зачем

В названиях официальных постановлений Казани один *коридор* иногда обозначает несколько этапов и очередей. Заголовок «Автомобильная дорога от ул. Несмелова до М-7» повторяется в документах об участках, которые реально начинаются далеко от Несмелова. Простое совпадение по слову вводит активиста в заблуждение.

`examples/kazan-road-archive-pilot.json` содержит **архивные контрольные заголовки**, редакционно сокращённые для тестирования, и не предназначен для заполнения живой ленты автоматически. Даты в примере — даты *актов*, не даты опубликования; `publishedAt` не выставляется. Ссылки части записей ведут на индекс документов, а не на отдельный PDF. Все записи помечены `demo=true`.

## Что реализовано

1. `LinearWork` извлекает структурированное описание: последний этап/участок, основная улица, границы `от ... до ...`, домовладения и километровые отметки (если они есть).
2. `Store.view()` для документа с уточнённым этапом ищет текстовые совпадения в локальном описании этапа, **не в общей протяжённой формулировке проекта**.
3. `OverpassStreets.fetchNetwork()` загружает ограниченную окрестную сеть OSM; в `streets` попадают только улицы, пересекающие полигон, в `contextWays` — дороги рядом с ним с полилиниями и OSM node IDs.
4. `RoadCorridor` по известной основной улице и двум именованным пересечениям строит маршрут по **общим OSM node IDs**. Простая геометрическая точка пересечения путей не считается перекрёстком: возможен путепровод.
5. Возвращаются `INTERSECTS_INFERRED`, `OUTSIDE_INFERRED`, `UNRESOLVED`. Это ориентировочное пространственное свидетельство, **не** `MATCH` и не официальная граница проектируемого линейного объекта.
6. Добавлена таблица `projects` в локальном JSON с идентификатором, названием и списком вручную подтверждённых событий. Доступны API и вкладка «Проекты» с хронологией.
7. `ProjectLinks` расширен поиском прямых ссылок на номер утверждающего постановления и одинаковых участков между перекрёстками — это только предложения, не автоматическое слияние.

## Режим и ограничения

Для реального геометрического эксперимента активист отмечает небольшой полигон на карте, нажимает «Улицы» (Overpass) и затем просматривает документ из архива. `Overpass` должен быть доступен; без связи со сторонним сервером статус только `UNRESOLVED`. Геометрический маршрут вычисляется **только** если оба конечных перекрёстка найдены в загруженном фрагменте. Если один далеко за границей расширенного bbox, результат `UNRESOLVED`, а не `OUTSIDE`.

Пара «от дома №... до дома №...» распознаётся, но координаты зданий пока не извлекаются. Формат «км 1+200 — км 2+900» разбирается численно, однако геометрия без паспорта дороги/линейной привязки неизвестна. Геометрия OSM условна и может отличаться от официального проекта. Сложные перекрёстки, параллельные полосы, мосты, неточные адреса и омонимия названий требуют ручной проверки. Для больших зон нужен полный граф дорог PostGIS/pgRouting или геопакет OSM.

## API

- `POST /api/areas/{uuid}/streets`: запрашивает OSM пересечения и соседние дорожные отрезки, сохраняет исходные OSM node IDs.
- `GET /api/events`: выводит `linearWork` и `corridors` с трассировкой причины оценки.
- `GET /api/projects`: все проекты, включая `timeline` (по опубликованию, затем дате акта, затем обнаружению).
- `POST /api/projects` с JSON `{ "name": "...", "notes": "..." }`.
- `GET /api/projects/{uuid}`: карточка и история.
- `POST /api/projects/{uuid}/events` с `{ "eventId": "..." }`: ручное прикрепление.
- `DELETE /api/projects/{uuid}/events` с `{ "eventId": "..." }`: открепление, сами события сохраняются.
- `GET /api/related?eventId=...`: предложения по идентификаторам и ссылкам на акты. Всегда `REVIEW`.
- `POST /api/import` с содержимым файла `examples/kazan-road-archive-pilot.json` — импорт исторических тестовых событий (явная команда пользователя; не вызывается при старте).

### Запуск и проверка

```bash
mvn clean package
java -ea -cp target/classes:target/test-classes ru.activisthelp.LinearProjectTest
java -jar target/pomosh-aktivistu-0.1.0.jar
```

Для тестирования по реальной публикации надо независимо сравнить результат с утверждённым PDF/графическими приложениями. Офлайн-тест `LinearProjectTest` использует **синтетические OSM-геометрии** и реальные заголовки, он не доказывает достоверность пространственной привязки на живой карте Казани.

Для геометрии по километражу нужна начальная точка и направление отсчёта конкретной дороги. Для домовых диапазонов — адресный реестр ФИАС/ГАР с координатами или геокодированием и проверкой адресных точек.
